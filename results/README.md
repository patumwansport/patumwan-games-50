# ระบบกรอกและอนุมัติผลการแข่งขัน (ฉบับ SQLite เดิม)

> **เลิกใช้แล้ว:** ระบบผลการแข่งขันย้ายไปที่ `/admin/results/` ซึ่งใช้บัญชีและฐานข้อมูล Supabase ชุดเดียวกับหน้าแอดมิน
> (ซอร์ส `admin-ui/src/results/`, ฐานข้อมูล `supabase/migrations/` ดู [supabase/README.md](../supabase/README.md))
> โฟลเดอร์นี้เก็บไว้อ้างอิงเท่านั้น ไม่ถูก deploy และลบทิ้งได้เมื่อไม่ต้องการแล้ว

ระบบแยกจาก Decap CMS (`/admin`) และระบบลงทะเบียนนักกีฬา ใช้ Node.js 22.13 ขึ้นไปและ SQLite โดยไม่ต้องติดตั้งแพ็กเกจเพิ่ม ข้อมูลกีฬาและโรงเรียนอ่านจาก `js/data` ของเว็บหลักตอนเริ่มระบบ

## เปิดใช้ในเครื่อง

```sh
cd results
npm start
```

เปิด http://localhost:5800 ใช้ชื่อผู้ใช้ `admin` รหัสผ่านสุ่มจะแสดงใน Terminal ครั้งแรก ต้องเปลี่ยนรหัสผ่านก่อนใช้งาน ฐานข้อมูลอยู่ใน `results/data/results.db` และไม่ถูกนำขึ้น Git

| ตัวแปร | ค่าเริ่มต้น | การใช้งาน |
|---|---|---|
| `PORT` | `5800` | พอร์ตของระบบผลการแข่งขัน |
| `HOST` | `127.0.0.1` | ตั้ง `0.0.0.0` หากรับการเชื่อมต่อจากภายนอก |
| `RESULTS_DATA_DIR` | `results/data` | โฟลเดอร์ข้อมูลถาวร ต้องสำรองข้อมูล |
| `RESULTS_ADMIN_PASSWORD` | สุ่มครั้งแรก | กำหนดรหัสผ่านแรกของ admin (8–128 ตัว มีอักษรอังกฤษและตัวเลข) ต้องเปลี่ยนเมื่อเข้าครั้งแรก |
| `TRUST_PROXY` | ปิด | ตั้ง `1` เมื่ออยู่หลัง reverse proxy ที่เชื่อถือได้และส่ง X-Forwarded-Proto / X-Forwarded-For |
| `PUBLIC_SITE_ORIGIN` | ว่าง | เช่น `https://games.example.ac.th` ไม่มี `/` ท้าย เปิด CORS เฉพาะ GET ของผลที่อนุมัติให้เว็บหลักอ่าน |

รันบนเครื่องหรือบริการ Node.js ที่มีดิสก์ถาวร เปิดผ่าน HTTPS ด้วย reverse proxy เช่นเดียวกับระบบลงทะเบียน **ไม่ใช้ SQLite บน Vercel Functions หรือ GitHub Pages** ตั้ง `TRUST_PROXY=1` เฉพาะเมื่อป้องกันการเข้าถึงเซิร์ฟเวอร์โดยตรงและ proxy เขียนทับ forwarded headers แล้ว `.vercelignore` ยกเว้นโฟลเดอร์นี้จากการ deploy เว็บ static

## ขั้นตอนใช้งาน

1. แอดมินกลางเข้า **บัญชีและสิทธิ์กีฬา** สร้างบัญชีฝ่ายเทคนิคและผู้ตรวจแยกกัน เลือกกีฬาที่มอบหมาย และส่งรหัสผ่านชั่วคราวให้เจ้าของบัญชีโดยตรง
2. บัญชีหนึ่งได้รับมอบหมายหลายกีฬาได้ แต่ในกีฬาเดียวกันเลือกได้หนึ่งหน้าที่: **ฝ่ายเทคนิค (กรอกผล)** หรือ **ผู้ตรวจ (อนุมัติผล)** ผู้ตรวจมองเห็นและตรวจได้เฉพาะกีฬาของตน แอดมินกลางจัดการได้ทุกกีฬา
3. ฝ่ายเทคนิคเพิ่มรายการแข่งขัน กำหนดรหัสไม่ซ้ำ วันที่ ระดับ รอบ สนาม และผู้เข้าแข่งขัน/ทีม บันทึกฉบับร่างได้แม้ยังกรอกคะแนนไม่ครบ
4. ตรวจทานหน้ารายละเอียด แล้วกด **ส่งผลให้ผู้ตรวจ** ต้องมีคะแนน/อันดับหรือสถิติครบทุกแถว ระหว่างรอตรวจจะแก้ไขไม่ได้
5. ผู้ตรวจตรวจคะแนนและเหรียญ แล้วเลือก **อนุมัติและเผยแพร่** หรือ **ส่งกลับให้แก้ไข** โดยระบุเหตุผล ผู้ส่งผลอนุมัติผลของตัวเองไม่ได้ รวมถึงแอดมินกลาง
6. รายการที่ส่งกลับจะแสดงเหตุผล ฝ่ายเทคนิคแก้ไข บันทึก และส่งตรวจใหม่

หนึ่งแถวหมายถึงหนึ่งผู้เข้าแข่งขันหรือหนึ่งทีม สำหรับกีฬาทีมให้กรอกทีมเป็นแถวเดียวและกำหนดเหรียญให้ทีมครั้งเดียว เพื่อไม่ให้นับเหรียญซ้ำจากรายชื่อนักกีฬาทั้งทีม ช่องคะแนน/อันดับและสถิติรับข้อความได้ เช่น `2`, `12.10`, `ชนะผ่าน`, `DNS` รูปแบบกติกาเฉพาะกีฬาให้ผู้ตรวจเป็นผู้ตรวจสอบ

**การแก้ไขผลที่เผยแพร่แล้ว:** บันทึกเป็นฉบับร่างใหม่ โดยเว็บยังแสดงฉบับอนุมัติล่าสุดจนกว่าจะอนุมัติฉบับแก้ไข หากฉบับเดิมผิดและต้องนำออกทันที ผู้ตรวจหรือแอดมินใช้ **ถอนผลออกจากเว็บไซต์** พร้อมเหตุผล การถอนทำให้ผลและเหรียญถูกนำออกเมื่อเว็บโหลดข้อมูลใหม่

เก็บประวัติฉบับที่แก้ ส่งตรวจ อนุมัติ ส่งกลับ และถอนผล พร้อมผู้ดำเนินการและเวลาไทยในหน้ารายละเอียด แอดมินดูประวัติการสร้างบัญชีและเปลี่ยนสิทธิ์ได้ที่ **ประวัติการใช้งาน** (500 เหตุการณ์ล่าสุด ฐานข้อมูลเก็บทั้งหมด) เมื่อแก้สิทธิ์ ปิดบัญชี หรือรีเซ็ตรหัสผ่าน session เดิมของบัญชีนั้นจะถูกยกเลิกทันที

## เชื่อมเว็บไซต์หลัก

1. Deploy ระบบนี้ เช่น `https://scores.example.ac.th` และตั้ง `PUBLIC_SITE_ORIGIN=https://games.example.ac.th` ให้ตรงกับโดเมนเว็บหลัก
2. ที่ `js/config.js` ของเว็บหลัก กำหนด:

   ```js
   resultsFeed: 'https://scores.example.ac.th/api/public/results',
   ```

3. เมื่อ `resultsFeed` ไม่ว่าง หน้าผลการแข่งขัน ตารางรายการ และสรุปเหรียญทั้งหมดจะใช้ผลอนุมัติจากระบบนี้แทน Google Sheet ไม่รวมสองแหล่งเข้าด้วยกัน เพื่อป้องกันการนับซ้ำ หาก API ขัดข้องจะแสดงข้อผิดพลาด ไม่ย้อนกลับไปแสดงผลเก่าจาก Sheet
4. เว็บเก็บแคช 30 วินาทีใน sessionStorage หน้าเว็บที่เปิดค้างให้รีเฟรชเพื่อโหลดผลใหม่ การเปลี่ยนค่ากลับเป็น `resultsFeed: ''` จะใช้ Sheet ตามเดิม
5. แจก URL ของระบบผลการแข่งขันให้เจ้าหน้าที่ ระบบนี้มีหน้าล็อกอินของตัวเอง ไม่ใช้บัญชี GitHub ของ CMS

ทดสอบการเชื่อมในเครื่อง: รันเว็บหลัก `python3 -m http.server 5500` ตั้ง `PUBLIC_SITE_ORIGIN=http://localhost:5500` ให้เซิร์ฟเวอร์ผลการแข่งขัน และตั้ง `resultsFeed: 'http://localhost:5800/api/public/results'` ชั่วคราวใน config (ไม่ใช้ HTTP บนระบบจริง)

Public API ส่งเฉพาะข้อมูลจากฉบับอนุมัติ: `{ matches: [...], results: [...] }` ไม่มีฉบับร่าง เหตุผลตรวจ ชื่อบัญชี หรือประวัติการทำงาน บัญชีเจ้าหน้าที่ใช้ HttpOnly / SameSite=Strict cookie อายุ 8 ชั่วโมง บังคับเปลี่ยนรหัสผ่านครั้งแรก เก็บรหัสผ่านแบบ scrypt และตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ทุกคำขอที่อ่านหรือเปลี่ยนผล

## ดูแลระบบ

ลืมรหัสผ่านแอดมิน ให้รันบนเครื่องที่เก็บฐานข้อมูล:

```sh
cd results
npm run reset-password -- admin
```

รหัสผ่านจะปรากฏครั้งเดียวใน Terminal session เก่าจะถูกยกเลิก หากเป็นบัญชีเจ้าหน้าที่ แอดมินรีเซ็ตผ่านหน้าจอได้

สำรองข้อมูลโดยหยุดเซิร์ฟเวอร์ก่อนคัดลอก `RESULTS_DATA_DIR` ทั้งโฟลเดอร์ (รวมไฟล์ WAL/SHM หากมี) แล้วเริ่มเซิร์ฟเวอร์ใหม่ เก็บสำเนานอก public directory และอย่านำฐานข้อมูลหรือรหัสผ่านขึ้น Git

## ตรวจสอบ

### ปรับหน้าตา UI

หน้าฝ่ายเทคนิคใช้ React shell, AnimatedSidebar, MenuSearch และ design tokens ชุดเดียวกับแอดมินหลักใน `admin-ui/` ซอร์สหน้าฝ่ายเทคนิคอยู่ที่ `admin-ui/src/results/main.tsx` และ `admin-ui/results-entry/index.html` ส่วนฟอร์มและขั้นตอนผลการแข่งขันอยู่ที่ `results/public/app.js` และสไตล์เนื้อหาอยู่ที่ `results/public/app.css`

หลังแก้ UI ให้ build จากโฟลเดอร์หลัก:

```sh
npm run build:results --prefix admin-ui
```

คำสั่งนี้ตรวจ TypeScript เฉพาะหน้าฝ่ายเทคนิคและคอมโพเนนต์ที่ใช้ร่วมกัน แล้วสร้าง `results/public/index.html` และ `results/public/ui/` โดยไม่ลบ API หรือฟอร์มเดิม ตัวเซิร์ฟเวอร์ผลการแข่งขันยังรันด้วย Node.js ได้โดยไม่ต้องติดตั้งแพ็กเกจสำหรับ runtime

### ทดสอบ API

```sh
cd results
npm test
```

ชุดทดสอบใช้ฐานข้อมูลชั่วคราวแยกจากข้อมูลจริง ครอบคลุมสิทธิ์ข้ามกีฬา การส่งกลับ อนุมัติ แก้ไขโดยคงฉบับเผยแพร่เดิม ถอนผล ป้องกันการแก้ทับ การยกเลิก session และการนำผลไปคำนวณเหรียญในเว็บหลัก

## ตารางแข่งขันรายวัน

เปิดเมนู **ตารางแข่งขัน** เพื่อจัดข้อมูลล่วงหน้า โดยระบุวัน เวลาเริ่ม–สิ้นสุด ประเภท รอบ กลุ่ม สนาม และหมายเหตุ แยกกิจกรรม เช่น รายงานตัว พัก และมอบเหรียญ ออกจากรายการที่มีคะแนนได้ ตารางนี้เป็นข้อมูลภายในของเจ้าหน้าที่ตามสิทธิ์กีฬา

บันทึกรายการแข่งขันโดยยังไม่มีผู้เข้าแข่งขันได้ แล้วกลับมากรอกผลภายหลัง ระบบไม่ให้ส่งตรวจจนมีผู้เข้าแข่งขันและผลครบ กิจกรรมไม่เข้าสู่ขั้นตอนอนุมัติผล และไม่รวมในผลหรือเหรียญสาธารณะ

กรองตามกีฬา วันที่ หรือคำค้น แล้วเลือก **ส่งออก Excel (CSV)** เพื่อดาวน์โหลดเฉพาะรายการตามตัวกรอง ไฟล์ใช้ UTF-8 พร้อม BOM สำหรับภาษาไทย การส่งออกนี้เป็นตารางกำหนดการ ยังไม่ใช่การนำเข้าไฟล์หรือรายงานผลคะแนน
