## หน้าแอดมิน (/admin)

เปิด `https://<โดเมนเว็บ>/admin/` แล้วเข้าสู่ระบบด้วย **ชื่อผู้ใช้และรหัสผ่าน** (หน้า `/admin/login.html`) เพื่อแก้ข่าวสารและข้อมูลใน `js/data/*.js` ผ่านฟอร์ม
ชื่อผู้ใช้คือส่วนหน้า @ ของอีเมลโรงเรียน เช่น อีเมล `kittiya.kul@satitpatumwan.ac.th` เข้าสู่ระบบด้วย `kittiya.kul` (อีเมลโดเมนอื่นกรอกอีเมลเต็ม)
กด "เผยแพร่" แล้วระบบจะ commit เข้า repo บน GitHub และ Vercel จะ deploy เว็บใหม่ให้เองภายในประมาณ 1 นาที
(ผลการแข่งขันและเหรียญยังกรอกใน Google Sheet ตามหัวข้อถัดไป)

- **ใครเข้าได้**: บัญชีใน Supabase Auth ที่ IT Admin สร้างที่เมนู **Role manager** ผู้ใช้ไม่ต้องมีบัญชี GitHub
  แก้เนื้อหาได้เฉพาะ Role **IT Admin** และ **CMS Editor** (ฝ่ายเทคนิคกีฬาและผู้ตรวจผลเข้าสู่ระบบแล้วไปที่ระบบผลการแข่งขัน `/admin/results/` ทันที)
- **บันทึกอย่างไร**: หน้าแอดมินส่งข้อมูลไปที่ `api/cms` ซึ่งตรวจการเข้าสู่ระบบ แล้ว commit ด้วย `GITHUB_TOKEN` ฝั่งเซิร์ฟเวอร์ (ผู้ใช้ไม่เห็น token)
  แก้ได้เฉพาะ `js/data/*.js` และรูป (jpg, png, webp, gif, avif) / PDF ใน `assets/images`, `assets/documents`, `assets/uploads` ไฟล์โค้ดอื่นแตะไม่ได้
- **รูป/ไฟล์ที่อัปโหลด** เก็บใน repo ตามโฟลเดอร์ของแต่ละช่อง (เช่น ข่าว → `assets/images/news/`, เอกสาร → `assets/documents/`)
  ไฟล์ละไม่เกิน 3 MB (แนะนำย่อรูปให้ไม่เกินประมาณ 1 MB) เพราะทุกไฟล์อยู่ใน repo ตลอดไป
- **ทุกการแก้ไขมีประวัติ** ใน GitHub (commit ระบุชื่อผู้ใช้ที่แก้) ย้อนกลับได้ด้วย `git revert`
- ไฟล์ `js/data/*.js` ต้องอยู่ในรูปแบบ `window.SiteData.<ชื่อ> = <JSON>;` (`admin/sitedata-format.js` เป็นตัวอ่าน/เขียน)
  ถ้าแก้ไฟล์เอง ใช้เครื่องหมาย `"` และไม่ใส่ comment ระหว่างข้อมูล ไม่อย่างนั้นหน้าแอดมินจะเปิดไฟล์นั้นไม่ได้
- เพิ่ม/ลดช่องที่แก้ได้ที่ `admin/config.yml` ([เอกสาร Decap CMS](https://decapcms.org/docs/widgets/))

### ตั้งค่าครั้งแรก (ทำครั้งเดียว)

1. **ตั้งค่า Supabase** ตาม [supabase/README.md](supabase/README.md) (สร้างตาราง, Edge Function `accounts` และ IT Admin คนแรก)
   แล้วใส่ `url` และ `publishableKey` ของโปรเจกต์ใน `admin/supabase.json` (เป็นค่าสาธารณะ ห้ามใส่ secret / service_role key)
2. **สร้าง GitHub token** ให้เซิร์ฟเวอร์ใช้บันทึก: GitHub > Settings > Developer settings > **Fine-grained tokens** > Generate new token
   - Resource owner: เจ้าของ repo (organization ก็ได้), Repository access: **Only select repositories** เลือกเฉพาะ repo ของเว็บนี้
   - Permissions > Repository permissions > **Contents: Read and write** (อย่างอื่นไม่ต้องให้)
   - ตั้งวันหมดอายุให้เลยวันจบงาน และจดไว้ว่าต้องต่ออายุเมื่อไร
3. Vercel > โปรเจกต์ > Settings > **Environment Variables** (เลือก Production) เพิ่ม แล้ว Redeploy

   | ชื่อ | ค่า |
   |---|---|
   | `GITHUB_TOKEN` | token จากข้อ 2 (เลือก Sensitive) |
   | `GITHUB_REPO` | ไม่บังคับ: `เจ้าของ/ชื่อ-repo` ว่าง = repo ที่ Vercel ดึงมา deploy |
   | `GITHUB_BRANCH` | ไม่บังคับ: ว่าง = `main` |

4. ตรวจว่าโปรเจกต์ Vercel เชื่อมกับ repo นี้ (Settings > Git) เพื่อให้ commit จากหน้าแอดมิน deploy อัตโนมัติ

### Role manager, Role และ Settings

เมนู **จัดการระบบ** ของ `/admin` มี **Role manager** (เฉพาะ IT Admin), **Role และสิทธิ์** และ **ตั้งค่า (Settings)** พร้อมปุ่ม **ออกจากระบบ** ด้านล่างเมนูซ้าย

| Role | ทำอะไรได้ |
|---|---|
| IT Admin | ทุกอย่าง รวมถึงสร้างบัญชี เปลี่ยน Role/กีฬา เปิด-ปิดบัญชี และรีเซ็ตรหัสผ่าน |
| CMS Editor | แก้ไขและเผยแพร่เนื้อหาเว็บไซต์ |
| ฝ่ายเทคนิคกีฬา | กรอกผลการแข่งขันของกีฬาที่ระบุ (ต้องเลือกกีฬาอย่างน้อยหนึ่งชนิด) |
| ผู้ตรวจผลกีฬา | ตรวจและอนุมัติผลของกีฬาที่ระบุ (ต้องเลือกกีฬาอย่างน้อยหนึ่งชนิด) |

- **เพิ่มบัญชี**: กด **Add** ใส่อีเมล ชื่อ Role และกีฬา ระบบสุ่ม **รหัสผ่านชั่วคราว** ให้บัญชีนั้นและแสดงครั้งเดียว (กดคัดลอกแล้วส่งให้เจ้าของบัญชีโดยตรง) ผู้ใช้ต้องตั้งรหัสผ่านใหม่ก่อนใช้งานครั้งแรก
  ระหว่างนั้นรายชื่อแสดงสถานะ **รอเปลี่ยนรหัสผ่าน**
- **รีเซ็ตรหัสผ่าน** สุ่มรหัสชั่วคราวใหม่ (แสดงครั้งเดียว) และบังคับเปลี่ยนใหม่ **ปิดใช้งาน** แทนการลบบัญชี (ประวัติยังอยู่ครบ) ทั้งสองอย่างมีผลทันทีแม้ผู้ใช้เปิดหน้าค้างไว้
- IT Admin เปลี่ยน Role หรือปิดบัญชีของตนเองไม่ได้ ให้ IT Admin อีกคนทำ จึงมี IT Admin เหลืออย่างน้อยหนึ่งคนเสมอ
- Settings เลือกขนาดตัวอักษร 20, 22 หรือ 24px ได้ โดยบันทึกเฉพาะเบราว์เซอร์ และปรับฟอร์ม CMS ในกรอบด้วย

### แก้หน้าตาหน้าแอดมิน (เมนูด้านซ้าย)

หน้า `/admin` เป็นแอป React ใน `admin-ui/` (โครงแบบ shadcn: `src/components/ui/animated-sidebar.tsx`, `src/lib/utils.ts`)
เมนูด้านซ้ายกำหนดใน `admin-ui/src/admin/nav.ts` ส่วนฟอร์มแก้ไขด้านขวาคือ Decap CMS (`admin/editor.html`) ที่แสดงในกรอบ
แก้แล้วต้อง build ใหม่และ commit ไฟล์ใน `admin/` ด้วย (Vercel ไม่ได้ build ให้)

```bash
cd admin-ui
npm install
npm run build           # เขียน admin/index.html และ admin/app/
npm run build:results   # เขียน admin/results/ (ระบบผลการแข่งขัน)
```

## ผลการแข่งขันและเหรียญจาก Google Sheet

มีระบบหลังบ้านสำหรับฝ่ายเทคนิคกรอกผลและผู้ตรวจประจำกีฬาอนุมัติที่ `/admin/results/` (ตารางแข่งขัน กรอกผล ส่งตรวจ อนุมัติ ถอนผล) ใช้บัญชีชุดเดียวกับหน้าแอดมิน IT Admin มอบหมายกีฬาที่ Role manager ฐานข้อมูลอยู่บน Supabase ดู [supabase/README.md](supabase/README.md) (`results/` เป็นฉบับ SQLite เดิมที่เลิกใช้แล้ว) เมื่อกำหนด `SiteConfig.resultsFeed` เว็บจะอ่านเฉพาะผลที่อนุมัติจากระบบนี้แทน Google Sheet; ถ้ายังไม่กำหนดจะใช้ Sheet ตามหัวข้อด้านล่าง

ข้อควรรู้สำหรับเจ้าหน้าที่:

- **ลงตารางหลายรายการ**: หน้า ตารางแข่งขัน > **นำเข้าจาก CSV** ใช้ไฟล์รูปแบบเดียวกับปุ่มส่งออก (กดส่งออกตอนยังไม่มีรายการจะได้แบบฟอร์มเปล่า) แก้ใน Excel แล้วบันทึกเป็น CSV ได้
  วันที่ใช้ `2027-12-02` หรือ วัน/เดือน/ปี (ปี พ.ศ. แปลงให้) รหัสที่มีอยู่แล้วจะถูกข้าม แถวที่ผิดจะแจ้งเป็นรายแถว
- **ทุกกีฬาต้องมีอย่างน้อย 2 บัญชี** คือฝ่ายเทคนิคและผู้ตรวจ เพราะผู้ส่งผลอนุมัติผลของตนเองไม่ได้ และหนึ่งบัญชีมีได้หนึ่ง Role (ตาม PRODUCT.md)
- **กีฬาประเภททีม** กรอกทีมละแถวเดียวและใส่เหรียญครั้งเดียว หน้ารายละเอียดจะเตือนเมื่อโรงเรียนเดียวกันได้เหรียญเดียวกันหลายแถว
- **ผลขึ้นเว็บหลังผู้ตรวจอนุมัติ** เว็บเก็บแคชไว้ 30 วินาที หน้าที่เปิดค้างไว้ต้องรีเฟรช

เจ้าหน้าที่กรอกผลใน Google Sheet แล้วหน้าเว็บอ่านไปแสดงเอง ไม่ต้องแก้โค้ดหรือมีเซิร์ฟเวอร์
สรุปเหรียญทุกหน้าคำนวณจากคอลัมน์ "เหรียญ" ในแท็บผลการแข่งขัน จึงกรอกเหรียญแค่ที่เดียว

### ตั้งค่าครั้งแรก

1. สร้าง Google Sheet ใหม่ 1 ไฟล์ มี 2 แท็บชื่อ `ตารางการแข่งขัน` และ `ผลการแข่งขัน`
   แถวแรกของแต่ละแท็บเป็นหัวคอลัมน์ตามตารางด้านล่าง (นำเข้าจาก `google-sheet/*.csv` ได้: ไฟล์ > นำเข้า)
2. ไฟล์ > แชร์ > **เผยแพร่ทางเว็บ** เลือกแท็บ `ตารางการแข่งขัน` และรูปแบบ **ค่าที่คั่นด้วยจุลภาค (.csv)** แล้วกดเผยแพร่ คัดลอกลิงก์
3. ทำซ้ำกับแท็บ `ผลการแข่งขัน`
4. ใส่ลิงก์ทั้งสองใน `js/config.js`:
   ```js
   sheet: {
     matchesCsv: 'https://docs.google.com/spreadsheets/d/e/.../pub?gid=0&single=true&output=csv',
     resultsCsv: 'https://docs.google.com/spreadsheets/d/e/.../pub?gid=123456&single=true&output=csv',
   ```
5. ตั้งสิทธิ์แชร์ไฟล์เป็น "จำกัด" (ไม่ต้องเปิด "ทุกคนที่มีลิงก์") ให้สิทธิ์แก้ไขเฉพาะเจ้าหน้าที่ และเปิดยืนยันตัวตนสองชั้นในบัญชี Google
   การเผยแพร่ทางเว็บเปิดเฉพาะ 2 แท็บที่เลือก แท็บอื่นในไฟล์ไม่ถูกเผยแพร่
   **ห้ามใส่ข้อมูลส่วนบุคคล** (เลขบัตร, เบอร์โทร, วันเกิด) ในแท็บที่เผยแพร่ เพราะทุกคนอ่านได้

แก้ข้อมูลแล้ว Google ใช้เวลาประมาณ 5 นาทีกว่าจะอัปเดตลิงก์ที่เผยแพร่ และเว็บเก็บแคชในเบราว์เซอร์อีก 2 นาที (`sheet.cacheMinutes`)

## ความปลอดภัย

- **Content-Security-Policy** (meta ในทุกหน้า): รันสคริปต์ได้เฉพาะไฟล์ในเว็บนี้ สคริปต์ที่ถูกแทรกเข้ามา (XSS) และ `onclick=` แบบ inline จะไม่ทำงาน
  จึงห้ามเขียน `<script>...</script>` หรือ `onclick="..."` ในหน้า ให้ใช้ไฟล์ `.js` และ `addEventListener` แทน
- **Tailwind เก็บไว้ในเว็บเอง** (`js/vendor/tailwindcss-3.4.17.js`) ไม่โหลดจาก CDN ภายนอก
- **ลิงก์/รูปจาก API หรือไฟล์ข้อมูล** ผ่าน `UI.safeUrl()` (กัน `javascript:` / `data:`) และ iframe ผ่าน `UI.embedUrl()` (เฉพาะ YouTube / Google Maps แบบ https)
  ถ้าจะฝังจากเว็บอื่น ให้เพิ่มโดเมนทั้งใน `EMBED_HOSTS` (`js/layout.js`) และ `frame-src` ของ CSP
- **ลิงก์เปิดแท็บใหม่** ใช้ `UI.NEW_TAB` (`rel="noopener noreferrer"`)
- **API** ต้องเป็น `https://` ไม่ส่งคุกกี้ และตรวจว่าได้ JSON รูปแบบ `{ data: [...] }`
- **Google Sheet** รับเฉพาะลิงก์ `https://docs.google.com/spreadsheets/...` ไม่ส่งคุกกี้ และทุกข้อความจาก Sheet ผ่าน `UI.esc()` ก่อนแสดง (ใส่ HTML/สคริปต์ใน Sheet จะแสดงเป็นข้อความธรรมดา)
- **กันการฝังหน้าเว็บใน iframe ของเว็บอื่น** (clickjacking) ใน `js/layout.js`
- **`vercel.json`** ส่ง header ความปลอดภัยฝั่งเซิร์ฟเวอร์ (CSP, `frame-ancestors`, HSTS, `X-Frame-Options`, `nosniff`)
  หน้า `/admin` มี CSP แยก: อนุญาต Decap CMS จาก unpkg.com (ล็อกเวอร์ชันและตรวจ `integrity`) และ `'unsafe-eval'` ที่ Decap ต้องใช้ เฉพาะหน้านี้
- **ล็อกอินหน้าแอดมิน**: ใช้ Supabase Auth (จำกัดการเดารหัสผ่านให้เอง และไม่บอกว่าชื่อผู้ใช้หรือรหัสผ่านผิด)
  `api/_auth.js` ตรวจ access token ทุกคำขอ และอ่าน Role/สถานะบัญชีล่าสุดจากตาราง `profiles` ปิดบัญชีหรือเปลี่ยน Role จึงมีผลทันที
- **บันทึกข้อมูล** (`api/cms.js`, `api/_github.js`): ทุกคำขอต้องล็อกอินและมาจากโดเมนเดียวกัน, เขียนได้เฉพาะ `js/data/*.js` และรูป/PDF ใน `assets`,
  ไฟล์ `js/data` ถูกเขียนใหม่จากข้อมูล JSON เท่านั้น (ใส่สคริปต์แปลกปลอมมาก็ถูกตัดทิ้ง)
  `GITHUB_TOKEN` อยู่ใน Environment Variables ของ Vercel เท่านั้น ห้ามใส่ในโค้ด Vercel ไม่ต้องมี service_role key ของ Supabase
  ถ้า deploy ที่อื่น ให้ตั้ง header เดียวกันในโฮสต์นั้น

## สิ่งที่ต่างจากเว็บต้นฉบับ

- หน้าผลการแข่งขันและสรุปเหรียญในเว็บเดิมฝังระบบ Blazor ผ่าน iframe จึงสร้างหน้าเหล่านี้ใหม่ด้วย JS
  โดยอ่านข้อมูลจาก Google Sheet (ดูหัวข้อ "ผลการแข่งขันและเหรียญจาก Google Sheet")
- หน้าเพลงประจำการแข่งขัน: ไม่ได้คัดลอกเนื้อเพลงและคอร์ดมา ถ้าต้องการแสดง ให้ใส่ใน `SiteData.anthem.lyrics`
  ที่ `js/data/content.js` แล้วหน้าเว็บจะแสดงให้เอง
- ระบบลงทะเบียนนักกีฬา (ระบบหลังบ้าน) อยู่ในโฟลเดอร์ `registration/` รันแยกด้วย Node.js ดูวิธีใช้ใน `registration/README.md`
- "ระบบลงทะเบียนนักกีฬา" ในเมนูยังไม่มีลิงก์ (แสดงในเมนูเป็นข้อความสีจาง กดไม่ได้) ใส่ลิงก์ได้ที่ `href` ของเมนู `register` ใน `js/config.js`
- หน้าแรกจัดโครงตามแม่แบบ sports-site-template: กรอบรูป Hero (`SiteConfig.heroImages`), นับถอยหลัง (`SiteConfig.startDate`), ชนิดกีฬา + ค้นหา และแถบผู้สนับสนุน (`SiteData.sponsors` ใน `js/data/content.js`) ตอนนี้เป็นกรอบเปล่า/ชื่อตัวอย่าง รอใส่ข้อมูลจริง
- หน้านโยบายความเป็นส่วนตัว (`privacy.html`) และเงื่อนไขการใช้งาน (`terms.html`) เขียนใหม่สำหรับปทุมวันเกมส์ โดยอิงหัวข้อจากเว็บคำมอกหลวงเกมส์ ครั้งที่ 49 แก้เนื้อหาได้ที่ `js/data/legal.js`
- หน้า `/schedule` และ `/results` ในเว็บเดิมเป็นข้อมูลตัวอย่าง (ทีมสมมติ) และไม่มีในเมนู จึงไม่ได้สร้าง

## การเชื่อมเมนูระบบลงทะเบียนนักกีฬา

ระบบเดิมอยู่ใน `registration/` ใช้ Node.js และ SQLite พร้อมบัญชีแอดมินและบัญชีโรงเรียนของตัวเอง ยังไม่ใช่บัญชีเดียวกับ Supabase ของหลังบ้านเนื้อหา

1. รัน `node registration/server.js` เพื่อเปิดระบบที่ `http://127.0.0.1:5700/`
2. เปิดเว็บหลักผ่าน `http://localhost:<port>/` หรือ `http://127.0.0.1:<port>/` เมนูลงทะเบียนจะเชื่อมพอร์ต 5700 ของเครื่องเดียวกันโดยอัตโนมัติ
3. เมื่อติดตั้งจริง ให้กำหนด `SiteConfig.registrationUrl` ใน `js/config.js` เป็น URL HTTPS ของระบบลงทะเบียน เมนูจึงเปิดใช้งานบนเว็บจริง

การอัปโหลดเว็บหลักไป Vercel ไม่ได้เริ่มเซิร์ฟเวอร์ Node.js/SQLite ของระบบลงทะเบียนให้ ต้องติดตั้งระบบนี้บนโฮสต์ที่รัน Node.js และเก็บฐานข้อมูล/รูปภาพถาวรได้ ข้อมูลเดิมใน `registration/data/` ใช้ต่อได้และไม่ควรนำขึ้น Git
